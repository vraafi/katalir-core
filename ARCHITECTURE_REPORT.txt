=== 1. PROJECT OVERVIEW ===
---
1.1 Nama: Nexus Agent Core (brand UI: Nexus Agent SaaS AI). Handoff ke AI reviewer (Claude) utk review, UX overhaul Apple-like minimalist, modernisasi 2026.
1.2 Tujuan: Visual AI Agent builder ala n8n/Flowise: chat + canvas workflow (Trigger->Agent->MCP), eksekusi async DAG, webhook, vault BYOK, metered billing Dodo+LiteLLM.

=== 10. BUSINESS LOGIC / FITUR ===
---
10.1 Fitur terimplementasi: (1) Chat AI multi-provider (Groq prioritas, Nvidia NIM, GitHub Models, Google Gemma/Gemini) + BYOK per-pesan + vault credential + riwayat sessions. (2) Visual Builder ReactFlow (drag-drop Trigger/Agent/MCP, connect animated, save/load Supabase, onNodeClick ConfigPanel, ExpressionEditor {{var}}, webhook URL card + copy, Jalankan Alur + terminal polling 2 detik). (3) Execution engine async DAG Trigger->Agent->MCP + NativeMCP (DDGS web_search 3 hasil + httpx http_request) + webhook BackgroundTasks POST /webhook/{id}. (4) Metered billing (FREE 10 per 22 jam, PLUS 30 per 24 jam + saldo Dodo block 402 + cost x3 multiplier + LEDGER litellm.completion_cost). (5) Vault Fernet (save/list, decrypt-inject unmetered). (6) Dodo webhook top-up.
10.2 User journey: Landing > Continue with Google (OAuth) > Chat (pilih provider, BYOK opsional, kirim prompt, riwayat tersimpan) > /builder (drag node, klik node, isi config ExpressionEditor, pilih AI Model tier, Simpan Alur, Jalankan Alur, terminal polling, lihat reply Gemma/MCP) > Trigger config (salin webhook URL) > Top-up Dodo saat saldo habis > Vault simpan kunci permanen.
10.3 Setengah jadi: validasi tier user (asumsi semua lolos); Redis Semantic Cache (placeholder); Google OAuth Sheets (rute dasar); model PRO/ULTRA (disabled); validasi signature Dodo (dev-bypass bila secret kosong); kolom email user_usage (ALTER manual).

16.5 BUG DIPERBAIKI (2): AUTENTIKASI BUTUH JARINGAN -> SEMUA ENDPOINT 401
- Gejala yang DILIHAT USER: "Ada masalah, coba lagi." (pesan generik UI) padahal
  backend sehat dan token Supabase masih hidup. Gejala ini MENYESATKAN; jangan
  dikejar sebagai bug frontend tanpa bukti jaringan.
- Akar masalah (dua lapis, keduanya nyata):
  (a) security.py memverifikasi token dengan MEMANGGIL Supabase
      (client.auth.get_user()) pada setiap request. Bila DNS/host Supabase tidak
      dapat dijangkau (kasus nyata: koneksi lokal terblokir), panggilan itu
      ConnectTimeout -> endpoint membalas 401 {"detail":"Token invalid: ConnectTimeout"}
      walau token SAH. httpcore memakai connect timeout untuk resolusi DNS
      sehingga "DNS hang" tampak sebagai "token invalid".
  (b) Setelah migrasi ke verifikasi lokal, ditemukan bug kedua: payload token
      Supabase selalu membawa aud="authenticated", sedangkan decode lama dipanggil
      tanpa expected audience -> InvalidAudienceError pada jalur HS256. Jadi jalur
      LOKAL pun menolak SEMUA token riil. Diperbaiki agar penanganan aud SERAGAM
      di kedua algoritma (ES256/HS256).
- Perbaikan: verifikasi JWT LOKAL memakai PyJWT + JWKS yang di-cache:
  sumber kunci = env SUPABASE_JWKS -> file .jwks_cache.json -> unduh sekali bila
  kosong. Hasil akhir: endpoint ber-JWT TIDAK lagi butuh jaringan untuk verifikasi.
- Bukti: 21 test deterministik tanpa jaringan di test_security_jwt.py LULUS
  (termasuk ES256 maupun HS256 dengan aud). Kunci publik ditanam via
  _seed_jwks.py (public key bersifat publik; aman disimpan).
- CATATAN OPERASIONAL: bila project Supabase memutar kunci (key rotation),
  .jwks_cache.json harus disegarkan, jika tidak token baru akan ditolak.

16.6 BUG DIPERBAIKI (3): MULTI-TURN KEHILANGAN KONTEKS
- Gejala: pesan ke-2 dalam sesi yang sama dijawab seolah tidak ada percakapan
  sebelumnya ("Anda belum meminta saya mengingat apa pun") walau riwayat TERSIMPAN
  benar di Supabase. Persistensi tampak sehat, jadi bug ini mudah salah didiagnosis

- Akar masalah: riwayat dibaca/ditulis ke database dengan benar, TETAPI tidak
  pernah DIKIRIM KEMBALI ke model saat menyusun prompt. Bukti kuantitatif:

- Perbaikan: /chat memuat riwayat sesi lalu menyertakannya sebagai contents;

- Bukti A/B di backend lokal (produksi-identik), sesi yang sama:
  - Turn-2 melanjutkan konteks: "Kode proyek yang Anda berikan adalah ZULFIKAR-99."
  - Kontrol (sesi BARU, prompt sama): "tidak memiliki konteks percakapan sebelumnya"
