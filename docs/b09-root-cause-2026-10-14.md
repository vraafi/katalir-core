# B-09: dari "flaky" → akar masalah nyata (14 Okt 2026)

## Ringkasan satu baris

B-09 **bukan flaky**. Ia gagal karena dua permintaan prefetch RSC yang
**selalu** 404 (`/builder.txt`, `/templates.txt`); apakah ia muncul di satu
run bergantung pada apakah tautan sidebar sempat masuk viewport.

## Cara menemukannya (perbaikan instrumen)

Sebelum perbaikan, `Probe._on_console` merekam HANYA `{type, text}`:

```
Failed to load resource: the server responded with a status of 404 ()
```

Tidak ada cara mengetahui resource MANA yang 404 → penyebabnya tidak bisa
dipastikan tanpa membuka DevTools manual. Itu sebabnya temuan sebelumnya
diklasifikasikan "flaky" (keterbatasan bukti, bukan kesimpulan).

Perbaikan (`tests/user_test/rus_core.py`): `_on_console` kini menyimpan
`url` + `line` dari `m.location`; `_on_pageerror` menyimpan `stack`; ada
`Probe.err_summary()`; B-09 menampilkan URL di kolom `actual`.

## Hasil setelah instrumen diperbaiki

`python tests/user_test/rus_run.py bug` → **FAIL**, dan sekarang URL-nya terbaca:

```json
{"type": "error", "text": "Failed to load resource: ... 404 ()",
 "url": "https://katalir.de5.net/builder.txt?_rsc=95XpWZDYBWq3k6mU", "line": 0}
{"type": "error", "text": "Failed to load resource: ... 404 ()",
 "url": "https://katalir.de5.net/templates.txt?_rsc=95XpWZDYBWq3k6mU", "line": 0}
```

`failed_requests` mengonfirmasi hal yang sama (`net::ERR_ABORTED`).

## Akar masalah (dibuktikan dari kode Next sendiri)

Runtime klien Next.js **15.5.27** membangun URL prefetch seperti ini
(`.next/static/chunks/1255-41a2740103efcd89.js`):

```js
(e = new URL(e)).pathname.endsWith("/")
  ? e.pathname += "index.txt"
  : e.pathname += ".txt";
```

Jadi untuk rute `/builder` ia meminta **`/builder.txt`** (payload RSC).

Sementara itu `nexus-frontend/scripts/export-out.mjs` — yang menggantikan
langkah `output: "export"` milik Next (karena shim safe-delete WorkBuddy
membatasi 50 penghapusan/giliran, lihat komentar kepala skrip) — **sengaja
hanya menyalin `.html`**:

```js
* Dari `.next/server/app`, yang ikut ke `out/` hanyalah HTML halaman —
* file `.meta`/`.rsc`/`.js`/`.map` adalah artefak server-side rendering dan
* TIDAK boleh ikut
```

Build menghasilkan `.next/server/app/builder.rsc`, `.next/server/app/templates.rsc`,
… tetapi `out/` **tidak memuat satu pun `.txt` RSC** — dibuktikan:

```
$ ls out/*.txt
out/robots.txt        # hanya ini
$ ls out/builder.txt out/templates.txt
MISSING builder.txt
MISSING templates.txt
```

→ Setiap prefetch RSC untuk tautan navigasi menabrak 404.

## Mengapa tampak "flaky"

Prefetch hanya terjadi saat tautan masuk viewport. B-09 mengklik tombol tema 6x
(menyebabkan reflow), jadi kadang tautan sempat ter-prefetch, kadang tidak:

| Run | `klik_berhasil` | `error_console` | Hasil |
|---|---|---|---|
| Regresi v4 (sebelum) | 6 | 2 | FAIL |
| Re-run akun baru (sebelum) | 6 | 0 | PASS |
| Run ini (sesudah) | 6 | 2 | FAIL |

Klik tema sendiri **selalu berhasil** (6/6) dan latar body berganti normal
(`rgb(250,250,250)`), jadi tidak ada bukti regresi tema sama sekali.

## Dampak

- **Fungsional: tidak ada.** Klik tautan tetap bekerja (navigasi penuh ke
  `/builder`, `/templates` — keduanya halaman nyata).
- **Non-fungsional:** 2 permintaan 404 terbuang per kunjungan `/chat`, plus
  galat konsol yang mengotori pemantauan galat dan membuat B-09 merah permanen.
- **Sudah ada sebelum perubahan hari ini** (kegagalan v4 juga menunjukkan 2
  galat konsol) — bukan regresi dari pekerjaan gemma.

## Usulan perbaikan (BELUM diterapkan — keputusan produk)

Di `export-out.mjs`, emit juga payload RSC dengan nama yang diminta klien:
salin `builder.rsc` → `out/builder.txt` (dan `index.rsc` → `out/index.txt`)
untuk setiap halaman. Itu meniru apa yang dilakukan langkah export Next sendiri.

**Kenapa TIDAK diterapkan sekarang:** ia mengubah pipeline deploy DAN mengubah
perilaku navigasi klien. Selama ini prefetch gagal → Next jatuh ke navigasi
penuh (yang bekerja). Setelah payload tersedia, Next akan memakai navigasi
klien; bila payload-nya tidak cocok, halaman yang rusak baru muncul SAAT DIKLIK
— risiko memperburuk. Perlu verifikasi terpisah (lokal + produksi) sebelum
dinyalakan. Karena di luar lingkup brief cleanup ini, dilaporkan alih-alih
diubah diam-diam.

## Status B-09

**Tidak ditandai "known flaky".** Ia deterministik: 404 terjadi setiap kali
prefetch menyala. Yang perlu diperbaiki adalah `export-out.mjs` (produk) atau
assertion B-09 (uji) — bukan stabilitas tes.
